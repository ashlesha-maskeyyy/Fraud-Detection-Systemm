# BuddhaAI: Nepal Mobile Payment Fraud Detection System

An end-to-end intelligent fraud detection and prevention system designed for the Nepalese mobile payment ecosystem. **BuddhaAI** uses a trained **Random Forest machine learning model** to analyze transaction behavior, assess fraud risk, and block suspicious transactions in real time.

The system includes a simulated customer-facing eSewa payment application, a FastAPI backend for fraud detection and transaction processing, and an administrative monitoring dashboard for reviewing transaction activity and AI-generated risk assessments.


---

## System Architecture

The system consists of three primary application components:

```text
                    ┌─────────────────────────┐
                    │   eSewa Client App      │
                    │   (Streamlit UI)        │
                    └────────────┬────────────┘
                                 │
                                 │ Transaction Request
                                 ▼
                    ┌─────────────────────────┐
                    │      FastAPI Backend    │
                    │        main.py          │
                    │                         │
                    │  Feature Engineering    │
                    │          ↓              │
                    │  Random Forest Model    │
                    │          ↓              │
                    │  Fraud Risk Assessment │
                    └────────────┬────────────┘
                                 │
                    ┌────────────┴────────────┐
                    │                         │
                    ▼                         ▼
          ┌─────────────────┐       ┌─────────────────────┐
          │  SQLite Database│       │ Admin Monitoring    │
          │     abc.db      │       │     Dashboard       │
          └─────────────────┘       │  (Streamlit UI)     │
                                    └─────────────────────┘
```


## Project Structure

```text
BuddhaAI
│
├── main.py
│   └── FastAPI backend and API gateway.
│       Handles transaction requests, feature engineering,
│       model inference, risk assessment, and transaction processing.
│
├── esewa_client.py
│   └── Simulated customer-facing eSewa payment application
│       developed with Streamlit.
│
├── admin_panel.py
│   └── Bank/admin monitoring dashboard.
│       Displays transaction history, fraud probabilities,
│       risk levels, and audit information.
│
├── database.py
│   └── Initializes the local SQLite database.
│
├── saved_models/
│   └── Contains the trained Random Forest model
│       stored in .joblib format.
│
├── requirements.txt
│   └── Python dependencies required by the project.
│
└── abc.db
    └── Local SQLite database generated after running database.py.
```

> **Note:** `abc.db` may not exist in a fresh clone of the repository. It is generated by running `database.py`.

# Running the System

The complete system requires **three separate terminal windows/tabs** because the backend, customer application, and administrative dashboard run as separate processes.

## Step 1 — Initialize the Database

Run:

```bash
python database.py
```

This initializes the local SQLite database and creates:

```text
abc.db
```

You only need to perform this step when the database needs to be initialized or recreated.

---

## Step 2 — Start the FastAPI Backend

Start the backend API with:

```bash
python -m uvicorn main:app --reload
```

The backend must remain running while using the customer and admin applications.

The API will normally be available at:

```text
http://127.0.0.1:8000
```

You can also access the automatically generated FastAPI documentation at:

```text
http://127.0.0.1:8000/docs
```

---

## Step 3 — Start the eSewa Client Application

Open a **new terminal tab** and activate the virtual environment.

Run:

```bash
streamlit run esewa_client.py
```

If the `streamlit` command is not recognized, use:

```bash
python -m streamlit run esewa_client.py
```

The Streamlit application will provide the simulated customer-facing eSewa interface.

---

## Step 4 — Start the Admin Monitoring Dashboard

Open a **third terminal tab**.

Run:

```bash
streamlit run admin_panel.py
```

Alternatively:

```bash
python -m streamlit run admin_panel.py
```

## System Workflow and Testing

To verify the system's fraud detection and real-time blocking capabilities, perform the following test scenarios.

### Scenario 1: Legitimate Transaction

**Input:**

* Amount: `500.00`
* Current Balance: `5000.00`

**Expected Result:**

The system identifies a standard payment pattern with zero mathematical error.

The eSewa UI should display a green **"Success"** message, and the transaction should be logged in the Admin Panel as **LEGITIMATE**.

---

### Scenario 2: Sophisticated Fraud Attempt — Account Draining

**Input:**

* Amount: `90000.00`
* Current Balance: `90000.00`
* Balance After Transaction: `0.00`

**Expected Result:**

The Random Forest model identifies the **"Total Account Drain"** behavioral pattern.

Even though the transaction is mathematically balanced, the high-value transaction combined with a zero-balance outcome triggers a security alert.

The eSewa UI should display:

**"TRANSACTION DENIED"**

---

### Scenario 3: Audit Verification

After running the tests above:

1. Open the **Admin Monitoring Dashboard** (`admin_panel.py`).
2. Click the **"Refresh Feed"** button.
3. Verify that both the successful payment and the blocked fraud attempt are visible in the history table.
4. Check their respective AI probability scores and risk levels.

The **"Refresh Feed"** option can be accessed by clicking the `>>` icon in the top-left.
